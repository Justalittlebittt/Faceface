# M16.23｜真正跨268页、六分片的仓颉引导研究试运行

## 已有事实与本次扩展

- M16.21 PP-OCRv5真实覆盖1925年原书两份PDF共268页，240页出现传统断语词汇，139页出现五官形态和传统断语OCR同行信号，非已确认的面相因果关系。
- M16.22首次真正衔接原版PDF、私有OCR与官方仓颉固定版本提示词和Qwen3 4B：7页OCR中选8条短句，模型实际请求8次，生成12条仅与**未校勘OCR字面**匹配的档案候选，4条输出被拒。零原图完整人工签认，零上线规则。实际运行：https://github.com/Justalittlebittt/Faceface/actions/runs/44493006476

本阶段 **M16.23** 采用与M16.21相同的六个真实原书页码分片。每个分片都要重新用实际PP-OCRv5扫描原图，扫描词汇并在私有环境保存OCR候选，然后**跨传统断语领域和原书页码均衡选取最多8条**，逐条调用真实Qwen3 4B。这避免只取第一批OCR行导致财富主题过度集中。

严格区分：

1. **真实原版268页再次OCR覆盖**：每页必须有来源 SHA、唯一页号和不重复的OCR统计。
2. **真实AI语义请求覆盖**：每片至多8个私有OCR片段、全部6片理论最多48次，实际计数以Actions为准；不等于对268页的每段原文完整语义提取，更不等于仓颉完整五类Extractor或Adler全书通过。
3. **验证与生产状态**：全文无人工完整页签认；任何模型草稿仅标 `source_unverified`、`archive_only`。全书可读结论、财富寿命品德判词不得自动上线。
4. **数据边界**：原PDF、全文OCR、私有OCR候选、模型结构化原文在临时私有Runner内；上传到GitHub的只有去文本化逐页元数据、候选计数、领域统计和拒绝原因。

### 运行
