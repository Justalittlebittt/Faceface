# Faceface M8｜真实模型单图扰动稳定性记录（2026-11-16）

## 目标与结论

此次目的不是证明“看相准确”，而是测试**相同图像**在温和的画质或取景变化下，10项实测比例、实验性形态标签及9张古籍局部关联是否意外翻转。使用Google MediaPipe官方公开示例人像（`portrait.jpg`），**未使用、保存、上传用户人脸照片或人脸关键点**。

- **已通过：** 使用真实MediaPipe的移动视口Chromium和Linux WebKit（近似Safari内核）分别运行“原图+6种变化”，合计**14次成功分析**。在所选变化下，**形态标签翻转0次，古籍关联增减0次**。这仅是**一个公开人像的重复性证据**，不能泛化为不同真人的识别准确率。
- **修正：** 第一版测试发现：此前在Chromium上，同样公开人像仅缩小至75%时，下巴纵向比例约从`0.218`到`0.220`，临界文本会跳档。修复了分类边界的数值舍入余量：原有实验性`margin`外增加`0.003`中性区间，新增对应单元回归。
- **修正测试有效性：** WebKit Canvas的`filter`结果不能可靠证明亮度/对比度变化生效，因此改用跨引擎一致的逐像素处理，并验证转换后平均亮度确实变化。这不属于Faceface正常产品图片预处理；仅供测试生成可控样例。
- **暂未完成：** 多真人、多角度、动态表情、不同手机型号、设备画质和人群上的误判/古籍误匹配率；未对10项比例阈值做群体统计标定；不能把这次测试记为真实iOS和Android双平台人脸质量验收。

## 可复核测试依据

代码：[PR #14](https://github.com/Justalittlebittt/Faceface/pull/14)；
[GitHub Web checks #43816880383](https://github.com/Justalittlebittt/Faceface/actions/runs/43816880383)；
[真实模型与扰动测试 #43816880366](https://github.com/Justalittlebittt/Faceface/actions/runs/43816880366)。

- 运行环境：GitHub Actions ubuntu-latest、Node 22、Playwright Chromium Pixel 7模拟设备及WebKit iPhone 13模拟视口；并非真实手机。
- 输入路径：相册文件选择组件 -> Faceface浏览器内图像缩放/Canvas -> 真实FaceLandmarker -> 十项面部描述 -> 9张古籍来源卡的条件判断。
- 对照：未改变的Google原始JPEG；变化：JPEG重压缩（质量75%）、亮度85%、亮度115%、对比度90%、画面中心轻微裁剪4%、缩小到原尺寸75%。每种变化均只对**同一人像**产生新图。
- 产物：`m8-stability-chromium.json`、`m8-stability-webkit.json`，GitHub Actions artifact保留14天。仅记录数字、标签差异、古籍卡片ID差异及聚合亮度，不存原图/变换图片/关键点。

## 最大绝对测量波动

下表的数字为各浏览器六个变化版本相对**同浏览器原图**的10项比例最大绝对差（不是与其他真人比较的误差，也不是识别准确率）。

| 测量字段 | Chromium最大差 | WebKit最大差 |
|---|---:|---:|
| 面部长宽比例 `face.aspect` | 0.026 | 0.021 |
| 眼部开合 `eyes.openness` | 0.013 | 0.015 |
| 鼻翼宽度 `nose.width` | 0.008 | 0.013 |
| 口部宽度 `mouth.width` | 0.007 | 0.010 |
| 下颌宽度 `jaw.width` | 0.005 | 0.006 |
| 双眼间距 `eyes.spacing` | **0.039** | **0.034** |
| 鼻部纵向 `nose.length` | 0.009 | 0.009 |
| 下巴纵向 `chin.height` | 0.011 | 0.011 |
| 口角走势 `mouth.corner` | 0.015 | 0.015 |
| 唇部可见厚度 `mouth.lip` | 0.007 | 0.007 |

**注意：** 双眼间距在此样例上的扰动最大，不宜仅凭此结果增加更精细的眼间距古籍门槛。无分类翻转是因为这个样例所处的类别位置与已有边界的关系，并不表示任何人都稳定。

## 原图匹配及有效变换的证据

- Chromium原图关联：`MY25-MOUTH-01`、`MY25-MOUTH-ARC-01`、`MY25-CHIN-WIDE-01`。
- WebKit原图关联相同；两种浏览器在原图上相对面部比例有细微差异，但**文化关联卡ID一致**。
- 样例转换前的JPEG重新编码平均亮度约`78.24`；逐像素亮度85%变换约`66.50`，亮度115%约`89.50`，在两浏览器得到相同的聚合亮度，证明确实进行了亮度改变。
- M8前的Chin边界显示问题已由额外中性缓冲消除；修复不会把比例解释成科学标准，也不会使古籍条件由“部分相似”升级为“完整相型”。

## 下一项验证

在取得明确同意及合法来源的不同真人照片后，**仅在测试者自己设备或获得明确授权的本地测试环境**进行不同光线/姿态/表情的重复测试，优先复核眼间距、脸部比例以及接近古籍触发阈值的样本。不要将真人照片、关键点或个人报告上传公开GitHub仓库。现有示例测试不能替代这一关。
