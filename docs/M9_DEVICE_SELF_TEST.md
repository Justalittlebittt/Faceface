# Faceface M9｜手机端本地双照片一致性验收

**公开测试站点：** https://justalittlebittt.github.io/Faceface/  
**功能上线证据：** [PR #15](https://github.com/Justalittlebittt/Faceface/pull/15) · [Web checks](https://github.com/Justalittlebittt/Faceface/actions/runs/43846703296) · [Chromium/WebKit 真模型操作与隐私回归](https://github.com/Justalittlebittt/Faceface/actions/runs/43846703313)。

## 目的和适用范围

这一检查只研究**同一人、两张独立照片**的面部形态描述、古籍局部关联是否一致。它不识别人脸身份、不能证明“看相准确”，也不能为人格、健康或命运提供事实推断。两张照片是否属于同一位自愿参与者，系统无法自动核实。

- 浏览器在本地分析照片；**不会自动上传用户照片、面部关键点、个人报告或本次对照结果到 Faceface 服务器**。
- 第二张照片分析时，界面只在当前页面内存保留第一张照片的**10项形态文字/比例摘要**，不保留第一张照片的像素、模型关键点或人脸身份特征。清除画面或页面卸载后结束对照；照片的浏览器对象URL会撤销。
- 首次启动或缓存失效时仍可能从 jsDelivr 和 Google Storage 下载 MediaPipe 模型/运行时；“无需上传照片”不等于“网站绝不访问第三方网络”，也不等于已经完成各地区合规审计。

## 真实手机如何测试

1. 在 Safari（iPhone）或 Chrome（Android）打开测试网址。请仅使用**本人或已明确同意参加本地测试的成年人的照片**。不应使用未经许可的陌生人面孔、公开网络真人头像或敏感人群照片。
2. 第一张照片：按主流程开启前置摄像头拍照，或从相册选择一张正面、光线正常的照片。确认显示10项观察及简洁/详细报告。
3. 在分析结果下方点击 **「对比同一人的另一张照片」**（English: *Compare another photo of the same person*），选择同一人的另一张照片。为了分析误差，可以选择同场景稍不同光线、自然表情或略有取景变化的照片。
4. 查看对照卡的两项数字：**形态描述或实验边界状态变化（/10）**和**古籍关联发生变化（/9）**。展开「查看全部比例及描述对照」，逐项查看指标变化、实验边界状态与古籍关联。M13还展示上／中／下脸段的近似照片百分比及百分点差异（不可测时显示缺失），但不构成古籍精确三停测量。
5. 最基础的校验是**同一张照片重复选择两次**：理论上应得到0项形态文字／分类状态变化、0张古籍关联变化，且若三段比例可用，两次应显示相应比例。如不是0，记录是哪个字段/古籍卡变化，并说明浏览器和设备型号。两张**不同**照片并没有预设必须0变化的硬要求，尤其表达与姿态本就会影响部分测量。
6. 点击「清除画面 / 重新拍摄」，确认对照界面被清除。可分别在中、英文状态下进行；另行验证报告文件是否能由用户主动保存。

## 允许记录哪些证据

可手动记下：测试手机系统及浏览器版本（不必带设备ID）、是否走摄像头/相册、10项中变化数量、9张卡片中变化数量、发生变化的**字段名称与方向**、失败错误文案。**不要上传真人照片、坐标数组、含面孔的截图、完整个人报告或可追溯身份的信息至公开 GitHub。** 即使比例差异被展示，也不代表它必然是匿名数据；不要求上传这些数字。

## 自动化已验证与仍欠缺的证据

- 已经通过： [CI #43846703313](https://github.com/Justalittlebittt/Faceface/actions/runs/43846703313) 中 Chromium 的模拟相机首次分析、WebKit 的本地照片首次分析，以及两引擎真实模型下的第二次本地照片对照；在使用**相同公开测试图**时结果为0/10和0/9。测试还检查未批准的外部HTTP请求、写请求及页面应用持久存储；旧的 M8 公开示例14次图像扰动回归继续通过。
- **没有验证：** 真实 iOS/Android 摄像头权限差异、不同成年人的拍照变异、侧脸/化妆/遮挡对形态分类的影响、统计误匹配率、各平台的实际缓存/浏览器供应商数据流与全面隐私合规。即便此地两图一致，也不能据此证明古籍对照解释有效。

## 下一轮研发判断标准

当多位自愿参与者的本地重复测试提供足够非识别性反馈后，再判断是否需要对 **`eyes.spacing`、`face.aspect`** 及古籍关联阈值做收紧或弃用。不要仅凭单张公开图和理论阈值改动实际判断。技术回归和主产品运行应当保留无图像、无特征持久化的原则。
