# Faceface｜总体实施规划与里程碑

> 更新于 2026-11-13。**HTTPS公开测试版已增加至10项形态描述、6张可追溯古籍来源卡与2张文化背景；35/35单测及Chromium/WebKit真实模型测试、上线后HTTP验证通过。用户曾实测早期手机本地照片→结果链路通过；新版本真机、多真人阈值、内容深度与隐私审计仍待验收。** 本规划规定开发顺序和可复核验收，不以纸面模拟或文档数量替代真实进度。

## 总目标与执行原则

**先跑通核心功能 → 再扩大全脸识别与古籍内容 → 最后完善并发布网站。**

核心功能指一条**真实**的端到端链路：**浏览器摄像头拍照 → 本地视觉模型 → 可读的多区域面部形态描述 → 有出处的古籍规则匹配 → 简洁/详细报告 → 用户主动保存**。优先证明这条链路在真实手机上能运作，而非先堆叠几十项特征或全书规则。

两条工作线：
- **A｜产品技术主线（优先）：** 真实照片识别及报告生成。首轮只使用少量**跨部位**特征和已核验的古籍规则来验证完整链路；首测数量不是正式版内容上限。
- **B｜知识库长线（并行）：** 《麻衣相法》1925年选定底本逐页归档、仓颉辅助提取、校勘与规则化。**完整收录始终是正式知识库目标，但不阻塞A线的真实技术验证和第一版网站公开发布。** 仅将有可靠出处且满足条件的规则接入当前报告。

完成分类严格区分：**设计 / 原页核查 / 模拟测试 / 真实浏览器测试 / 公开上线**。文档记录不得自行升级为实现或验收结论。

## 阶段一｜核心闭环真实验证（最高优先）

### M0｜最小工程与研究交接

- [x] 创建 Faceface GitHub 仓库和项目文档。
- [x] React + TypeScript + Vite移动优先响应式Web工程已提交；GitHub CI实际依赖安装、类型检查、生产构建、9/9模拟单测通过；Chromium使用官方公开人像运行真实MediaPipe并输出五区域描述。**手机真机与完整产品闭环仍未完成。**
- [ ] **按需**迁入 V2.5 47候选字段、V2.6分层、V2.7/V2.8古籍映射、旧v1.6代码中的必要且可追溯部分；标注来源与“已核验/模拟/未验证”，不得把历史测试当生产证据。
- [ ] 明确首轮少量跨区域可观察特征及对应已核查古籍条目；不为数据搬迁而阻塞可运行网页。

**Gate M0：** 仓库中有能启动的真实网页和带来源标记的最小数据，不只是说明文档。

### M1｜真实摄像头 → 本地模型 → 自然语言

- [ ] 用户主动授权浏览器前置摄像头；支持拍照、重拍、拒绝授权、关闭摄像头；不请求麦克风。
- [ ] 在浏览器端运行**真实**人脸关键点/轻量模型，不使用伪造坐标代替推理；验证模型许可与移动端负载。
- [ ] 首轮从约 **6–12 个**候选字段中选择可实测、古籍有对应价值的**多区域**形态，优先覆盖脸型、眼、鼻、口、下颌中的不同区域；不是只研究眉毛。
- [ ] 为每个字段明确几何/视觉依据、阈值或分类逻辑、可见性、干扰因素和 `unknown`；输出普通人能读懂的自然语言，而非仅输出点坐标。
- [x] **用户人工真机验证：** 至少一部手机已从本地选择照片并看到分析记录（未记录机型/操作系统/浏览器，不代表前置摄像头路径和双平台均通过）。
- [ ] 用不同的实际人脸及角度/遮挡情况检验区分度、重复运行一致性和未知状态；至少验证 Android Chrome、iOS Safari 真机。
- [ ] 用网络请求及本地存储检查，核实照片、关键点、形态描述不外传和不默认持久化，离开页面停止相机。

**Gate M1：** 真实手机照片能稳定产出多个部位的可复核形态描述；失败和不可见信息不编造；具有真机及隐私检查证据。

### M2｜有据匹配 → 双报告 → 保存

- [ ] 将 M1 的统一特征 ID 与**少量已经对照原页**的《麻衣相法》规则连通，记录版本、卷章、页码、必要/组合条件与例外。
- [ ] 匹配状态区分“条件符合 / 局部相似 / 条件不足”，不能把现代宽泛形容直接包装为古籍完整相型。
- [ ] 同一份匹配结果生成**默认简洁版**与**可免费展开的详细版**；历史观点、现代生活建议和事实观察分别标注。
- [ ] 验证不同真实照片确实产生有依据的不同描述/内容；相同输入同版本结果一致；双版不矛盾。
- [ ] 用户主动保存报告；照片/面部特征/报告不默认上传或保存，禁止强制注册及人格确认问卷。

**Gate M2：** 至少一条从**真人拍照到实际报告并保存**的可重复演示闭环，附有可追溯古籍来源和网络/存储证据。**M2完成才算“核心功能已验证”；不等同于正式内容覆盖完成。**

## 阶段二｜内容广度与报告质量扩展

### M3｜扩展识别与可调用规则

- [ ] 依据**真实识别稳定性 × 古籍解释价值 × 手机性能**，从47项候选词典中逐步扩展；以**多区域覆盖**为导向，眉部保持少量权重，无法可靠识别的一律保留未知状态。
- [ ] 将核验过的古籍形态描述和条件逐批映射至可观测字段，完成冲突、重叠、组合条件核查；不追求为每条古籍相形单独训练模型。
- [ ] 扩充简洁/详细报告的有效内容与差异化表现，拒绝重复套话和脱离可观察事实的断言。
- [ ] 有需要才增加耳部补拍、八卦有据取象及更多可观察部位；保证跳过补拍不影响主流程。

**Gate M3：** 相比阶段一，已通过真机验收的区域/规则覆盖扩大，报告丰富度有可比较的真实案例；不以未经验证的规则数量作为成果。

### 并行 B 线｜全书原典档案（不设为网站首发阻塞项）

- [ ] 合规取得选定1925年《麻衣相法》五卷扫描源，建立来源、页/卷/篇目录、许可与转录状态。
- [ ] 逐页归档原文、图谱、历史断语、例外、异文及不可由照片判断的内容；仓颉仅辅助抽取和核查，不能替代无损档案。
- [ ] 目标：底本页与篇章覆盖率 100%，缺损明示；历史全文记录与**可由照片触发的规则集分开统计**。
- [ ] 经过来源核查的新增规则可持续接入 M2/M3，不必等待全书完成。

**Gate B：** 全书完整性与可追溯性独立验收；**不是首版网站上线 Gate**。未经授权不在公开仓库存放原扫描或可能受保护的全文。

## 阶段三｜产品完善与公开上线

### M4｜手机体验与发布验收

- [ ] 打磨移动端完整流程：引导 → 正脸拍照 → 分析 → 简洁报告 → 详细报告 → 自主保存；耳部需要时可补拍或跳过。
- [ ] 处理无脸/多人、权限拒绝、光线或遮挡、弱网、设备不支持与低性能手机；验证主流 iOS Safari / Android Chrome。
- [ ] 完成首发语言及经校核译文，保护传统文化娱乐定位，不将外貌推断宣称为科学人格、健康、命运事实。
- [ ] 检查 HTTPS、模型资源许可、部署/回滚、访问地区基础合规、隐私声明、网络与存储证据；不虚称“网站不处理任何个人信息”。
- [x] 已在 https://justalittlebittt.github.io/Faceface/ 部署免费的 HTTPS 技术测试站点；GitHub Actions 已验证首页与隐私页面可用。至少一部手机由用户反馈本地照片→分析结果链路通过；完整正式上线仍待验收。

**Gate M4：** 普通用户可在公开测试网址独立完成完整流程，关键设备可用、无脸数据外传证据可核查，具备发布所需的基础说明与测试结果。

### M5｜上线后流量验证，商业化后置

- [ ] 先收集**不包含照片、面部特征或个人报告**的必要访问/使用指标与真实反馈，验证是否有人愿意使用。
- [ ] 在有稳定真实流量且值得商业化时，再评估 AdSense、个人收款、身份税务资料、第三方广告隐私与地区同意要求；广告不进入摄像头拍摄页。
- [ ] 广告申请、银行收款办理和商业化税务研究**不作为当前开发主线或首版上线前置条件**；但实际发生收入时依法履行相关义务。

**Gate M5：** 有可复核的访问与使用反馈，才讨论广告变现；不把访问数、广告审核通过或收益写成已实现事实。

## 减法纪律与下一步

- 不以“新增文档/模拟案例/单部位眉相研究”替代可运行软件；**不为迁移旧版所有资料而推迟M1。**
- 不因首测只做少量特征而削弱最终全脸和全书目标；不把古籍知识的“传统观点”包装成科学结论。
- 单项功能避免重复抽象、重复判空、无必要防并发和过度防御；对真实数据、隐私、相机权限保留必要校验。
- 阶段验收只检查最关键的可观察结果，不增加无效文档门槛。

**下一项可执行任务：** 已部署10项观察、6张来源卡、两张文化背景，以及数据驱动多条件古籍匹配。下一阶段优先扩大**非重复、跨脸部区域、原文可核查且条件可判的传统形态语言**，改善简洁/详细报告的有效差异化；不为增加字段而增加字段。并行开展本版真实手机回归、多真人分类一致性、前置摄像头、文件保存和隐私网络验收；旧版单机成功仍不能代替新版双系统验收。
